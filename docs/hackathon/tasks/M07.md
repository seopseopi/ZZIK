# M07 · 사진 상세·원본 다운로드

> `plan.json`에서 생성한 프롬프트입니다. 수정 후 `python scripts/render_hackathon_prompts.py`를 실행하세요.

아래 지시를 작업 프롬프트로 사용한다. 먼저 저장소의 `AGENTS.md`, `docs/hackathon/COMMON.md`, `docs/hackathon/OWNERSHIP.md`, `docs/API_CONTRACT.md`, `contracts/README.md`를 읽는다.

- 주관: 2번 프론트·UI 통합
- 협업: 3번, 1번
- 우선순위: P0 · 원문 단계: 2
- 선행 작업: M06

## 목표

권한 있는 멤버가 상세 정보를 보고 원본·선택 ZIP을 내려받는다.

## 출발 상태

로컬 원본/ZIP 검증됨; S3 서명 URL 실검증 필요. 이 상태는 계획 작성 시점의 기준이며 이번 작업의 완료 증거가 아니다. 기존 구현과 테스트를 읽고 부족한 부분만 변경한다.

## 확인할 파일

- `frontend/src/App.tsx`
- `backend/app/main.py`
- `backend/app/storage.py`

## 연결 계약

- `GET /api/photos/{photo_id}`
- `GET /api/photos/{photo_id}/download`
- `GET /api/albums/{album_id}/download`

요청·오류는 `contracts/openapi.json`, 상세 응답 의미는 `docs/API_CONTRACT.md`, Python 호출 경계는 `contracts/python-interfaces.json`을 따른다. 응답 타입 자동 생성은 아직 없으므로 프론트 타입과 실제 응답도 함께 확인한다.

## 진행 순서

1. `git status`와 선행 PR을 확인하고 M 번호가 있는 작업 브랜치를 사용한다.
2. 현재 기능을 재현하고 완료 조건별로 구현됨/부족함/외부 검증 필요를 나눈다.
3. 주관 범위의 변경을 구현한다. 공유 API·DB·화면 변경은 통합 담당과 조정한다.
4. 아래 검사를 실행하고 정상·실패 경로를 확인한다. 외부 검증은 샘플로 대체하지 않는다.
5. 기능 단위 커밋과 PR에 계약 변경·검사 결과·남은 조건을 기록한다.

## 완료 조건

- [ ] 다운로드 원본 SHA-256이 업로드와 동일
- [ ] 미참여 계정·다른 앨범 ID 접근 차단
- [ ] S3 서명 URL은 만료하며 실제 촬영/위치 정보 없는 경우 미상 표시

## 검증

`TEST_DATABASE_URL`은 전용 `_test` DB, `ZZIK_E2E_DATABASE_URL`은 로컬 전용 `_e2e` DB를 지정한다. 설치와 예시는 [조립 가이드](../ASSEMBLY.md)를 따른다.

```bash
.venv/bin/python -m pytest -q backend/tests/test_api_integration.py backend/tests/test_album_management.py
.venv/bin/python scripts/run_integration.py
.venv/bin/python scripts/check_harness.py
```
