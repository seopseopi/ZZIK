# M01 · 3-Tier 기본 연결

> `plan.json`에서 생성한 프롬프트입니다. 수정 후 `python scripts/render_hackathon_prompts.py`를 실행하세요.

아래 지시를 작업 프롬프트로 사용한다. 먼저 저장소의 `AGENTS.md`, `docs/hackathon/COMMON.md`, `docs/hackathon/OWNERSHIP.md`, `docs/API_CONTRACT.md`, `contracts/README.md`를 읽는다.

- 주관: 1번 AWS 인프라·배포
- 협업: 3번
- 우선순위: P0 · 원문 단계: 1
- 선행 작업: 공통 계약 확정

## 목표

Web→FastAPI→DB 및 별도 worker를 구성하고 각 실행 모드의 검증 상태를 구분한다.

## 출발 상태

로컬·Docker Compose 전체 실행/E2E/컨테이너 재시작 검증됨; AWS 3-Tier 실배포 미검증. 이 상태는 계획 작성 시점의 기준이며 이번 작업의 완료 증거가 아니다. 기존 구현과 테스트를 읽고 부족한 부분만 변경한다.

## 확인할 파일

- `compose.yaml`
- `infra/nginx.conf`
- `backend/app/db.py`
- `backend/app/main.py`
- `docs/AWS_DEPLOYMENT.md`
- `backend/app/routers/system.py`

## 연결 계약

- `GET /api/health/live`
- `GET /api/health/ready`

요청·오류는 `contracts/openapi.json`, 상세 응답 의미는 `docs/API_CONTRACT.md`, Python 호출 경계는 `contracts/python-interfaces.json`을 따른다. 응답 타입 자동 생성은 아직 없으므로 프론트 타입과 실제 응답도 함께 확인한다.

## 진행 순서

1. `git status`와 선행 PR을 확인하고 M 번호가 있는 작업 브랜치를 사용한다.
2. 현재 기능을 재현하고 완료 조건별로 구현됨/부족함/외부 검증 필요를 나눈다.
3. 주관 범위의 변경을 구현한다. 공유 API·DB·화면 변경은 통합 담당과 조정한다.
4. 아래 검사를 실행하고 정상·실패 경로를 확인한다. 외부 검증은 샘플로 대체하지 않는다.
5. 기능 단위 커밋과 PR에 계약 변경·검사 결과·남은 조건을 기록한다.

## 완료 조건

- [ ] Web만 외부 진입점이며 App·DB 접근 범위를 문서화
- [ ] AWS 완료는 실제 Web/App/RDS 경유 요청으로 증명; 로컬/Docker 성공과 별도 표시
