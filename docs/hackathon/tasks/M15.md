## 목표

앨범 내부 얼굴을 묶고 사람이 병합·분리·계정 연결을 바로잡는다.

## 출발 상태

모의 AWS/DB 검증됨; 실제 컬렉션 동작 미검증. 이 상태는 계획 작성 시점의 기준이며 이번 작업의 완료 증거가 아니다. 기존 구현과 테스트를 읽고 부족한 부분만 변경한다.

## 확인할 파일

- `backend/app/grouping.py`
- `backend/app/analysis.py`
- `backend/app/models.py`
- `backend/app/routers/groups.py`
- `frontend/src/features/curation/Groups.tsx`

## 연결 계약

- `POST /api/albums/{album_id}/face-groups/analyze`
- `POST /api/face-groups/merge`
- `POST /api/face-groups/{group_id}/split`

요청·오류는 `contracts/openapi.json`, 상세 응답 의미는 `docs/API_CONTRACT.md`, Python 호출 경계는 `contracts/python-interfaces.json`을 따른다. 프론트 타입은 OpenAPI에서 생성한다. 계약 변경 시 스냅샷과 타입을 함께 갱신하고 `npm --prefix frontend run types:check` 및 실제 응답 검사를 수행한다.

## 진행 순서

1. `git status`와 선행 PR을 확인하고 M 번호가 있는 작업 브랜치를 사용한다.
2. 현재 기능을 재현하고 완료 조건별로 구현됨/부족함/외부 검증 필요를 나눈다.
3. 주관 범위의 변경을 구현한다. 공유 API·DB·화면 변경은 통합 담당과 조정한다.
4. 아래 검사를 실행하고 정상·실패 경로를 확인한다. 외부 검증은 샘플로 대체하지 않는다.
5. 기능 단위 커밋과 PR에 계약 변경·검사 결과·남은 조건을 기록한다.
