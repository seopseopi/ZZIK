## 완료 상태의 구분

- **코드 있음:** 해당 연결/기능이 코드에 존재한다.
- **로컬 검증:** PostgreSQL·API·worker·샘플 분석으로 검사했다.
- **실환경 검증:** 해당 커밋을 실제 S3·Rekognition·배포 서버에서 확인했다.
- **서비스 완료:** 필요한 실환경·권한·복구·처리량 검증까지 충족했다.

현재 로컬 핵심 서비스와 정적 체험판이 있으며 S3·Rekognition 어댑터도 있다. 교육용 콘솔에서 합성 사진의 얼굴 검출·비교를 확인했으며, 계정 제약과 앱 역할 연결의 남은 검증은 [AWS_EDU_VALIDATION.md](../AWS_EDU_VALIDATION.md)를 따른다. 앱 분석 함수의 합성 사진 실검증과 로컬 DB·사진의 백업 복원 리허설을 추가했다. 실제 사진 정확도·원격 다중 사용자·AWS 복원·2,000장 성능은 아직 검증하지 않았다. AWS 리소스를 새로 만들 때는 계정·리전·기존 자원·예산을 확정해야 한다.

## 앞으로의 기준본과 starter

현재 `d06ca14`는 기존 구현을 보존하는 출발 커밋이다. AWS까지 검증된 최종 기준 태그가 아니다. 서비스 검증을 마친 커밋에 기준 태그를 만들고, 별도 starter 브랜치에서 구현 경계를 비운다. 숨겨진 완성 코드를 붙여 넣는 대신 각 M 프롬프트의 계약과 검사로 재구현·조립할 수 있는지 리허설한다. 대회의 기존 코드·사전 준비 허용 범위도 확인한다.

현재 로컬 연습판은 AWS 최종 기준본보다 먼저 준비한다. CI 통과 커밋 `2ffb4a9`의 공통 기반을 제공하고 30개 기능 단위를 비운다. [제작·검증 범위](../../starter/README.md)를 따르며, 기계적 기준 구현 복원과 팀원의 독립 재구현을 구분한다.
