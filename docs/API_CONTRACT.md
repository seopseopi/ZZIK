# ZZIK integration contract
All endpoints /api. Session cookie authentication; JSON errors {code,message,details?}. IDs strings UUID. Dates ISO. All writes JSON except multipart file. Response objects direct; lists {items,total,page,page_size}. 담당 3번이 models/API/storage/worker/seed를 통합하고, 4번은 analysis/grouping/메타데이터·품질, 5번은 렌더링·버전·승인, 2번은 프론트 공통 타입·화면, 1번은 인프라를 담당한다. 자세한 경계는 [OWNERSHIP.md](hackathon/OWNERSHIP.md), 요청 스키마와 호출 경계는 [contracts](../contracts/README.md)를 따른다.

Auth: POST /auth/register {name,email,password}, /auth/login {email,password} -> {user:{id,name,email},csrf_token}; GET /auth/me -> same. POST /auth/logout. Header X-CSRF-Token for writes, login/register exempt. Demo login uses normal email/password, seeded only by explicit command: jisu@moacut.local / MoacutDemo123!, minji@moacut.local same. GET /config -> {face_provider,storage_backend,demo_enabled}.
Albums GET/POST /albums body {name,description?,timezone?}; GET/PATCH/DELETE /albums/{id}; POST /albums/join {code}. Album {id,name,description,timezone,photo_count,member_count,cover_url,invite_code,created_at,members:[{id,name,email,role}],people:[Person]}. Owner manages invite rotate POST /albums/{id}/invite. DELETE /albums/{id}/members/{user_id}.
Album owners may update details, rotate invite codes, remove other members, or delete the album. A non-owner member may DELETE their own membership to leave. Photos stay when members leave; person-account links are cleared, and affected approval requests/final versions require review again. Rejoining does not restore earlier approvals.
GET /albums/{id}/analysis-status -> {provider,mode:sample|live,stats:{pending,processing,completed,failed},total,recorded_runs,calls,elapsed_ms,failures:[{photo_id,filename,error:string|null}],oldest_pending_at:string|null}. Failures are limited to the latest 20. recorded_runs/calls/elapsed_ms sum stored attempts, including failures and retries; elapsed_ms is accumulated execution time, not wall-clock wait time. oldest_pending_at is the earliest available_at of a pending job. POST /albums/{id}/reanalyze-failed -> {queued}; members may requeue inactive failed jobs, idempotently. Pending jobs and active worker leases are preserved.
Person {id,name,user_id?,reference_url?,link_status?}. POST /albums/{id}/people multipart {name,file,user_id?}. GET /albums/{id}/people. PATCH /people/{id} {name?,user_id?} owner proposes link, target accepts via POST /people/{id}/accept-link. DELETE /people/{id}.
Photos GET /albums/{id}/photos?page=1&page_size=40&filter=all|mine|solo|group|no_faces|review|final&people=id,id&match=all|any&tag=&q=&sort=newest|oldest|captured&date=YYYY-MM-DD -> {items,total,page,page_size,stats:{pending,processing,completed,failed}}. POST same multipart {file,request_id} -> Photo. Photo {id,album_id,filename,thumbnail_url,display_url,original_url,width,height,created_at,captured_at,capture_timezone?,latitude?,longitude?,location_name?,analysis_status,analysis_error,analysis_provider,analysis_mode,face_count,unknown_faces,people:[{id,name,user_id,source}],tags:[],purpose,selected,final_version_id,board_status,versions?:[],recommendation?,quality?}. GET/PATCH/DELETE /photos/{id} PATCH {purpose?,selected?,note?}. PUT /photos/{id}/people {person_ids:[]} maintains manual exclusions and invalidates approval snapshots. POST /photos/{id}/reanalyze failed only. GET /photos/{id}/file?kind=original|thumbnail|display&download=true; URLs point here. GET /photos/{id}/download?version_id=... (omitted original).
Version {id,photo_id,number,name,parent_id,author:{id,name},created_at,brightness,saturation,renderer_version,preview_url,review_requested,needs_review,targets:[{user_id,name,approved}],approval_count,target_count,consensus,is_final,comments:[{id,author,body,kind,created_at}]}. GET/POST /photos/{id}/versions body {name,parent_id?,brightness:0.25..2,saturation:0..2}. POST /photos/{id}/preview {brightness,saturation} -> image/jpeg bytes; same renderer as export. GET /versions/{id}/file?download=true. POST /versions/{id}/request-review {confirmed:true} snapshots effective people mapped users; no_faces uploader default, unlinked blocks. POST/DELETE /versions/{id}/approval. POST /versions/{id}/final. POST /versions/{id}/comments {body,kind:comment|change_request}.
GET /albums/{id}/board -> {selection:Photo[],editing:Photo[],review:Photo[],final:Photo[]}. GET /albums/{id}/recommendations -> {groups:[{id,photos:Photo[],recommended_ids:[],reasons:{id:[]}}]}. GET /albums/{id}/face-groups; POST /albums/{id}/face-groups/analyze; PATCH /face-groups/{id} {name?,person_id?}; POST /face-groups/merge {group_ids}; POST /face-groups/{id}/split {face_ids}. Actual AWS groups adapter only; fixture must disclose sample/unavailable honestly.
GET /notifications -> {items,total}; POST /notifications/{id}/read.

Photo detail additionally exposes uploader_id and analysis_metadata {model?,calls?,elapsed_ms?,analyzed_at?}. Photo DELETE requires uploader or album owner. Album access locks the album before photo and job rows; membership changes/deletion and worker writes use an exclusive album lock to avoid access or storage races.

Agent interface: image_service.inspect_image(data, content_type=None) -> dict with width,height,mime,sha256,captured_at (string/null),capture_timezone,latitude,longitude; prepare_image(data,max_size=1600)->JPEG bytes; render_image(data,brightness=1,saturation=1,max_size=None)->JPEG bytes; thumbnail_image(data)->JPEG bytes; quality_metrics(data)->dict including perceptual_hash,sharpness,exposure. storage.get_storage() object put(key,data,content_type='application/octet-stream'),get(key)->bytes,delete(key),exists(key). analysis.analyze(data, references=[{id,name,data}], original_hash=None,album_id=None)->dict {faces:[{box:{left,top,width,height},person_id,similarity}],face_count,unknown_faces,tags,provider,mode,model,calls,elapsed_ms}; analysis.validate_reference(data,original_hash=None)->dict or raises AnalysisError(code,message). The backend integration owner maintains worker transactions and DB models. JSON stores faces/analysis metadata; PhotoPerson rows preserve manual additions/exclusions. Python parameter names are checked by scripts/check_harness.py; return-value semantics require integration tests.
