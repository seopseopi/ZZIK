# 빈 저장소에서 시작하는 찍 / ZZIK 연습

**정정: 대회 출발점은 빈 저장소다.** `starter/local-v1`은 이미 인증·스키마·계약·디자인·테스트가 제공되는 부분 구현 연습이므로 이번 대회 모의 연습의 출발점으로 사용하지 않는다. `.starter-state.json`, `starter.py`, `assembly_plan.py`, 기존 30개 stub, 기존 테스트 통과 기록도 새 저장소의 전제나 완료 증거가 아니다.

이 폴더는 사람이 각 개발 에이전트에 전달하는 **자연어 지시문 묶음**이다. 구현 코드·DB 스키마·OpenAPI·테스트·이미지·Docker 설정을 포함하지 않는다. 새 저장소에 기존 ZZIK 소스나 생성물을 복사·clone·cherry-pick·archive·검색해서 답안으로 가져오지 않는다. 이번 연습에서는 아래 지정한 동일 저장소의 빈 연습 브랜치만 사용한다. 기존 코드 브랜치는 가져오지 않는다. 공식 문서와 공개 라이브러리는 대회가 허용한 범위에서 사용한다. 프롬프트 자체의 반입 허용 여부도 실제 규정을 따른다.

## 시작 상태 — 파일 0개 또는 지시문 Markdown만

애플리케이션 코드·package.json·Dockerfile·DB 스키마·테스트는 모두 현장에서 새로 만든다. ZIP은 채팅에 전달하는 문서이며 저장소에 미리 압축을 풀 필요가 없다. 커밋이 전혀 없으면 원격 브랜치도 아직 없을 수 있으므로 1번만 지정된 이름으로 첫 커밋을 만든다. 2~5번은 그 커밋을 받은 뒤 시작한다. 주최 측이 Markdown만 넣은 초기 커밋을 제공하면 그대로 보존한다.

## 이번 연습: 다섯 명이 처음에 할 일

연습 원격은 [seopseopi/ZZIK](https://github.com/seopseopi/ZZIK), 제출 기준은 [practice/empty-5person](https://github.com/seopseopi/ZZIK/tree/practice/empty-5person), 실행 ID는 `practice-01`이다. 브랜치는 파일 0개인 독립 루트 커밋 `152b45c48ccfbfa451c26891bbb3d27e81c0f6fb`로 생성했다. 연습이 시작되면 파일이 추가되며, 다시 비우지 않는다. 이 기록은 실제 5명 협업 완료 증거가 아니다.

1. 저장소 관리자가 5명에게 쓰기 권한을 부여하고 각자 자신의 GitHub 계정으로 로그인한다.
2. 각자 새 폴더에 아래 명령으로 복제하고 AI에서 그 폴더를 연다.

   ```bash
   git clone --single-branch --branch practice/empty-5person https://github.com/seopseopi/ZZIK.git ZZIK-practice
   cd ZZIK-practice
   ```

3. 1번에게 역할별 GitHub 계정 5개를 알려준다. 각자 자기 `ROLE_0N.md` 내용 전체를 AI에 전달한다. 문서는 저장소 밖에서 전달해도 된다.
4. **동시에 실행해도 된다.** 1번이 G0를 준비하고 나머지는 설정 확인·검토·대기를 수행한다. G1 기준이 공유된 뒤 다섯 역할이 병행 구현한다.
5. AI 세션이 실행 중이면 GitHub 요청 확인·응답·커밋·push·PR·리뷰·조건 충족 병합을 수행하도록 지시돼 있다. 각 도구의 권한 확인과 세션 종료/토큰 한도는 프롬프트로 없앨 수 없다. 종료되면 같은 프롬프트로 원격 상태부터 재개시킨다.

`--single-branch`이므로 다른 역할 브랜치는 프롬프트의 정확한 ref fetch 절차로 가져온다. 모든 연습 PR은 제출 기준을 명시하며 기존 `main`에는 병합하지 않는다. 실제 GitHub 5계정 종단 동작은 이번 연습으로 확인해야 한다. 기존 코드가 들어 있는 브랜치는 사용하지 않는다.

## 팀이 준비할 사실

제공 저장소 OWNER/REPO, 실제 제출 브랜치, 1~5번 GitHub 계정, 실행 ID, 사용 가능한 AI/네트워크/프롬프트 반입 범위를 한 번 정한다. 비밀번호/토큰은 각자 로그인하고 공유하지 않는다. AWS 자원 생성은 현재 보류다. 대회 계정·예산·배포 승인이 별도로 생기기 전에는 로컬 검증만 수행한다.

연습 때에도 기존 starter를 가져오지 않고 **파일이 없는 독립 연습 브랜치 또는 새 빈 저장소**를 사용한다. 실제 대회에는 주최 측 저장소를 사용한다. 검증에는 외부에 공개하지 않는 임시 로컬 Git 저장소만 만들었다. 새 GitHub 저장소나 AWS 자원은 만들지 않았다.

## 5인 흐름 검토 후 추가한 조건

- G0/bootstrap, G1/backend·frontend, G2 역할 PR의 브랜치를 구분한다.
- G1에서 React 프로젝트도 2번이 먼저 만든다. 5번의 보정 화면 작업과 중복 생성하지 않는다.
- G1 기준 커밋·계약 해시·실제 검사를 기록하고 모두 같은 커밋에서 시작한다.
- backend 의존성/모델은 3번, frontend 의존성/App은 2번, Compose/CI는 1번이 통합한다.
- 계약 변경·리뷰 head 변경·최종 base 변경 시 재검사를 거친다.

검증 결과는 별도 `VERIFICATION.md`에 있다. 이는 최소 fixture와 로컬 Git으로 작업/충돌/복구 흐름을 재현한 검사이며, 제품 완성·실제 5계정 GitHub·5개 AI 세션 검증은 아니다.

## 서로 요청하고 답하는 방식

각 역할 셀에 동일한 통신 규칙을 포함했다. 요청마다 고유 ID와 담당 계정·실행 ID·대상 커밋을 기록한다. `REQUESTED → ACK → READY → APPLIED`로 수신과 적용을 구분한다. 결과를 원격에서 가져와 검사한 요청자만 완료로 표시한다. 리뷰 댓글은 실제 GitHub PR 승인을 대체하지 않는다.

실행 중인 세션은 시작/재개·작업 단위 종료·의존 대기 중 수신함과 리뷰를 확인한다. 중복 전송·늦은 응답·변경된 head·순환 대기·네트워크 실패에 대한 처리 규칙도 포함했다. 이슈/댓글 개수는 실제 요청에 따라 늘어나며, 이것을 PR 리뷰 횟수로 세지 않는다.

**사람이 각 PC에서 세션을 시작해야 한다.** 종료된 AI를 자동 실행하거나 서로 다른 AI 제품의 권한 확인을 우회하는 상시 실행기는 없다. 무응답이면 재실행 필요 상태를 보고하며, 무인 자동 운영 성공으로 표시하지 않는다. 실제 GitHub 계정 5개 간 왕복 통신은 아직 미검증이다.
