# 5인 빈 저장소 흐름 검증 결과

판정: 최초 안내에 부족한 부분이 있어 수정했다. 수정된 작업 순서와 Git 통합 방식은 아래 **로컬 시뮬레이션 범위에서 통과**했다. 실제 제품·GitHub·다섯 AI 세션의 성공을 보장하지 않는다.

## 발견하고 수정한 부분

1. 2번 React 프로젝트 생성과 5번 편집 화면 구현이 충돌/대기할 수 있었다. G1에 2번 프론트 기반 PR을 넣었다.
2. G1 완료를 말로만 알려 각자 다른 커밋에서 시작할 수 있었다. 계약 해시·검사 결과와 기준 커밋을 공유하도록 정했다.
3. G0/G1에서 닫힌 역할 PR을 G2에서 재사용할 수 있었다. bootstrap/foundation/work 브랜치를 단계별로 나눴다.
4. 공유 모델·의존성 파일의 동시 변경 기준이 부족했다. backend는 3번, frontend는 2번, 인프라는 1번이 통합하도록 정했다.
5. 검토 후 새 커밋 또는 제출 브랜치 변경을 처리하는 기준이 부족했다. head/base 변경 시 갱신·재검사를 명시했다.

## 실제 실행 범위

새 로컬 bare Git 저장소 1개와 역할별 clone 5개, 재개 확인용 clone 1개를 생성했다. 기존 ZZIK 구현은 넣지 않았다. Git/검사 명령 159회를 실행해 13개 시나리오를 확인했다. 검증용 코드에는 작은 데이터 계약과 처리/표시 함수만 있으며 React·FastAPI·PostgreSQL 서비스를 구현한 것이 아니다.

| 검사 | 결과 |
|---|---|
| 5개 clone이 커밋 없는 동일 원격에서 출발 | 통과 |
| 3번이 루트 커밋 전에 구현 브랜치를 시작할 수 없음을 확인 | 통과 |
| 3번 계약·실제 assertion 검사와 2번 프론트 경계 준비 | 통과 |
| 전원이 같은 G1 커밋에서 역할 브랜치 생성 | 통과 |
| 다른 역할이 없는 단독 브랜치에서 전체 통합 검사가 실패 | 예상대로 실패 확인 |
| 2·5번 공통 파일 충돌 후 양쪽 변경을 보존해 해결 | 통과 |
| 의도적으로 넣은 계약 위반으로 후보 검사 실패, 제출 브랜치 미반영 | 통과 |
| 작성 역할의 수정 커밋 재통합과 이전 검토 SHA 불일치 확인 | 통과 |
| 새 coordinator clone에서 원격 후보 상태로 재개 | 통과 |
| 통합 중 제출 브랜치 변경 감지 | 통과 |
| 후보 갱신 후 재검사 및 새 head 확인 | 통과 |
| 최종 병합에 다섯 역할의 실제 시뮬레이션 커밋 포함 | 통과 |
| 오래된 역할 브랜치의 제출 브랜치 push가 거부됨 | 통과 |

시뮬레이션 커밋 작성자는 `SIMULATED ROLE N - not a teammate`로 표시했다. 해당 로컬 원격 이력은 GitHub에 올리지 않았으며 팀원의 실제 기여 이력으로 사용하지 않는다. 검토 SHA 비교는 로컬 조건 검사이며 GitHub review API를 실행한 것이 아니다. 첫 실행에서 검증 도구가 Python 캐시를 추적해 checkout이 막혀, 도구의 초기 .gitignore를 보완한 뒤 새 빈 디렉터리에서 전체를 다시 실행했다.

## 아직 검증하지 않은 부분

- 다섯 독립 AI가 이 프롬프트로 찍 전체 기능·테스트를 새로 구현하는 것
- 실제 다섯 GitHub 계정의 PR 생성·교차 리뷰·branch protection·merge 권한
- 각자 OS·AI 도구·토큰 한도·세션 대기와 재개
- 실제 React/FastAPI/PostgreSQL E2E, AWS 3-Tier 배포·장애 복구
- 대회 시간 안의 완료 가능성과 실제 평가·반입 규정

제작자용 재현 도구는 준비 저장소의 `scripts/verify_empty_repo_flow.py`다. 새 외부 디렉터리를 `--output`으로 지정한다. 프롬프트 ZIP에는 이 도구나 검증용 구현 코드를 넣지 않는다. 이 문서는 검증 결과를 전달하는 자료이며 참가자가 공식 저장소에 복사할 필수 파일이 아니다.

## 실제 연습에서 예상되는 문제와 반영한 대응

아래는 위험 검토와 프롬프트 수정이며, 각 팀원의 실제 환경에서 재현·해결을 확인한 결과는 아니다.

| 예상 문제 | 프롬프트에 반영한 대응 | 현장에서 확인할 것 |
|---|---|---|
| 파일/커밋이 없어 origin/main checkout 실패, 다섯 명의 초기화 경쟁 | 1번만 지정 브랜치에 최초 커밋, 나머지는 fetch 후 출발 | 최초 push 허용 여부 |
| 보호 브랜치 때문에 최초 커밋 불가 | 관리자에게 Markdown 초기 커밋 또는 초기화 권한 요청 | 주최 측 관리자 조치 |
| G1 프론트 리뷰 담당이 모호함 | 5번이 frontend 검토, 1번이 backend·G1 기준 검토, 3번이 병합 조정 | 각 계정 리뷰 권한 |
| OS·설치 버전·Docker 차이 | G1 각 PC 실행 검사와 동일 명령/lockfile | 실제 5대 환경 |
| 3번에게 변경이 몰리거나 공유 파일 덮어쓰기 | 파일 소유자와 변경 요청 형식 고정, 각 역할은 독립 구현 | 처리 시간/인원 가용성 |
| 단독 역할에서 다른 기능이 없어 E2E 실패 | Draft 조기 공유, 역할 검사와 후보 전체 검사를 분리 | 실제 제품 E2E |
| migration 순서 충돌·기존 데이터 손상 | 3번 순서 통합, 빈 DB/기존 전용 테스트 DB 모두 검사 | 생성된 migration 실행 |
| 토큰 소진·세션 종료·리뷰어 부재 | 역할별 인계 기록 push, 사람이 재기동·대체 리뷰어 배정 | 구독/재개 가능 여부 |
| CI 권한·필수 검사·squash 제한 | G0 정책 확인, 우회 금지, 실제 반영 대응표 기록 | 원격 GitHub 정책 |
| fixture를 실제 AI로 오해 | 실행 모드·화면·결과·README에 fixture 명시 | 실제 얼굴 분석은 별도 |
| 대회 시간 내 17개 기능 미완성 | 종료 시각·우선순위 기록, 핵심 연결 흐름 우선 검증, 기능별 상태 보고 | 실제 소요 시간·범위 결정 |

절차로 예방할 수 있는 모호함은 수정했다. 계정 권한·토큰·대회 정책·실제 구현 실패까지 해결되었다고 단정하지 않는다. 실제 5명 연습을 한 번 거쳐야 제품 완성도와 소요 시간을 판정할 수 있다.

## 역할 간 요청/응답 추가 검증

기존에는 정기 확인과 이슈/PR 요청만 지시했고, 수신·완료 확인과 재전송 기준이 부족했다. 다섯 역할 셀 모두에 동일한 통신 절차를 넣었다. 실제 원격을 확인하는 주기, 고유 요청 ID, 요청/수신/결과/적용 단계, 변경된 head 처리, 작성자·수신자 확인, 모든 페이지 조회, 시간 초과 후 확인, 인계와 순환 대기 해소를 명시했다.

`python3 scripts/verify_role_messages.py`의 **로컬 메시지 상태 모델 12개 검사**가 통과했다.

1. 다섯 역할이 차례로 요청·응답하고 각 단계에서 저장된 상태로 재개
2. 응답 유실을 가정한 동일 이벤트 재시도에서 중복 기록 방지
3. 동일 이벤트 ID에 다른 내용을 넣으면 거부
4. 다른 저장소/실행 ID 및 알 수 없는 역할 거부
5. ACK·READY를 완료로 취급하지 않음
6. 결과 제공자가 요청자의 적용 확인을 대신할 수 없음
7. 검사 실패·잘못된 결과 SHA이면 요청을 열어 둠
8. 요청과 다른 head의 응답 거부
9. 수신 확인 또는 결과 SHA가 없는 진행 거부
10. 상대가 중단돼도 요청 보존, 복귀 후 수신 확인
11. 대체된 이전 요청 응답이 새 요청을 완료하지 않음
12. 순환 의존 감지 및 독립 계약 단계로 분리 후 순환 해소

이 도구는 로컬 JSON 저장소와 가상 역할을 사용하는 순차 상태 모델이며 실제 통신 프로그램이나 GitHub 어댑터가 아니다. 원격 SHA 존재·실제 테스트 결과·계정 인증·GitHub 리뷰는 모델에 주어진 입력으로 취급한다. GitHub 페이지 조회·네트워크 재시도·시간 기반 재촉·실제 AI의 규칙 준수는 여기서 실행 검증하지 않았다. 다섯 PC·계정·AI가 실제로 주고받는 종단 검증은 남아 있다. 원격에 테스트용 댓글이나 가짜 승인을 게시하지 않았다.

문서의 확인 주기는 활성 세션에 대한 지시다. 종료된 세션을 자동 기동하는 상시 실행기는 제공하지 않는다. 멈춘 세션은 사람이 다시 실행해야 한다. 이 범위를 넘어 완전 무인 협업이 검증됐다고 표현하지 않는다.
