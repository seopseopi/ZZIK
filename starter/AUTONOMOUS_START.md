> **출발점 정정:** 사용자가 대회는 빈 저장소에서 시작한다고 확정했다. 이 starter는 공통 구현이 있는 별도 부분 연습용이다. 실제 대회 모의 연습은 `prompts/empty-repo/README.md`와 자기 역할 셀을 사용하며 기존 코드를 가져오지 않는다.

# 팀이 한 번 준비하고 Kiro가 조립하는 시작점

## 대회 전

1. 1~5번 실제 담당자와 자기 GitHub/Kiro 계정을 배정한다.
2. 연습은 `starter/local-v1`을 clone하고, 공식 대회는 주최 측이 준 저장소를 clone한다. 반입 허용 확인 전에는 이 starter를 공식 저장소에 복사하지 않는다.
3. `starter/team.example.json`의 비어 있는 저장소·base·5명 로그인과 규정 근거를 채워 `.zzik-assembly.json`으로 공유한다. 개인 인증은 각자 하고 토큰/비밀번호는 파일에 넣지 않는다.
4. 1번 Kiro가 허용된 시작 파일 도입을 준비하고 3번 Kiro가 검토한다. 이미 파일이 있으면 덮어쓰지 말고 차이를 검토한다. 제공 저장소의 이력과 규칙을 유지한다.
5. 각 팀원이 자기 checkout에서 [시작 프롬프트](../docs/hackathon/PR_WORKFLOW.md)의 번호만 바꿔 Kiro를 시작한다.

## 그다음 Kiro가 맡는 것

30개 구현 단위와 역할별 순서는 이미 `starter/manifest.json`에 있다. `python3 scripts/assembly_plan.py plan`이 저장소 입력 검증 후 브랜치·교차 검토자·통합 순서를 출력한다. 각 Kiro는 자기 단위 구현·검사·커밋·역할 PR 갱신과 배정된 다른 역할 검토를 수행한다. 3번 Kiro는 실제 역할 커밋을 별도 후보 브랜치에 모아 전체 검사를 통과시킨 뒤 최종 PR을 병합한다. 1번 Kiro가 최종 후보를 검토한다.

사람에게 매번 다음 작업·커밋 시점·PR/merge 여부를 물어보지 않는다. 실제 권한이나 인증이 없고, 규정/요구사항이 충돌하거나 원격 필수 리뷰가 사람을 요구하는 경우만 해당 결정을 요청한다. Kiro 실행 환경의 명령 승인은 도구 설정을 따른다. 세션 종료 후에는 같은 프롬프트로 원격 상태에서 이어간다.

## 완료 기준과 현재 한계

커밋 수 목표는 없다. 실제 구현 단위와 검사, 실제 발견·수정한 리뷰 이력을 남긴다. 과거 준비물을 대회 중 작성한 이력으로 위장하지 않는다. 최종 통합의 전체 검사가 통과해야 조립 완료다. AWS 3-Tier 배포·중단 시연은 별도 승인·환경을 기다린다.

현재 제공한 것은 실행 규칙·설정 검증기·역할 프롬프트다. 5개 Kiro 세션 자동 기동/메시지 전달 서비스나 공식 저장소 branch protection 설정은 제공하지 않는다. 실제 Kiro에서 5명이 이 과정대로 조립한 결과는 아직 검증 전이다.
